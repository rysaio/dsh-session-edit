# dsh-session-edit

DSH 会话内的「编辑」分页：就地修改模型可见的思考、回复文字与工具调用，改完立即生效，不落盘、不弹窗、不悬浮。

## 安装

本插件以 DSH profile 的 bundle 形式装载。在 profile 目录（`~/.dsh/profiles/<profile>`）执行：

1. 装进 profile 依赖：

   ```sh
   pnpm add github:rysaio/dsh-session-edit
   ```

   本地开发直接链到工作副本：

   ```sh
   pnpm add link:<本仓库路径>
   ```

2. 在 profile `package.json` 的 `dsh.profile.bundles` 数组末尾加上 `"dsh-session-edit"`，保留原有项：

   ```json
   "dsh": {
     "profile": {
       "bundles": ["...原有项", "dsh-session-edit"]
     }
   }
   ```

3. 重启 DSH，会话标题栏出现「编辑」分页。

## 用法

打开任意会话，在标题栏的视图标签里点「编辑」。页码内显示你自己的输入、模型的思考过程、回复文字和工具调用；工具结果只读，挂在对应调用下面。

- 回复和思考块原地就是文本框：改完点「保存」（Ctrl+Enter）生效。
- 一次只读末尾 30 条，顶端「加载更早的对话」继续往前翻；首次进入落在末尾那条回复的开头。
- 编辑中切走（切到对话、切到别的会话）再回来，未保存的草稿、滚动落点、思考与工具调用的展开状态、原文预览都会还原，草稿仍标「未保存」，不会写入会话。
- 思考块到下一个思考块之间的工具调用合成一个折叠层，默认收起，标题带条数和工具名；展开后每条调用直接显示名字和参数两栏，参数必须是 JSON 对象，保存时校验；链尾有「收起工具调用」。
- 改过的块会标「已改」，旁边有「原文」和「还原」：「原文」就地预览原始内容，「还原」把该块写回原文（立即对模型生效）。
- 思考过程默认折叠，只露一行摘要，点「▸ 思考 …」展开或收起；展开后超过 200px 在块内滚动。
- 展开工具调用后，每条调用下面有配对的工具结果，只读，超过 4000 字截断并标「已截断」；改调用不会重新执行工具，原结果保持原样。
- 用户消息旁的「跳到回复 ↓」滚动到对应回复；顶部「最新 ↓」跳到末尾。
- 每条仍有可见内容的模型回复右上角有「从这里分叉」：以该回复为最新一轮复制出新会话，改稿一并带入，随后在 Chat 里继续。
- 图省事不选写入方式：没有「仅落盘」「仅页面渲染」，保存即写投影。

## 模型工具

Host 侧还注册七个面向模型的 Tool（profile 挂载了 `tools` 服务时）：

| Tool | 作用 |
|---|---|
| `session_edit_read` | 读会话快照：reasoning、回复、工具调用；默认最近 2 条、不带工具结果 |
| `session_edit_poll` | 读增量窗口：每个子会话最近 4 条 assistant 的 reasoning + 回复；`waitMs` 可等到下一条或 turn end |
| `session_edit_apply` | 改一个已有块：reasoning / text / tool-call；目标必须 idle |
| `session_edit_prompt` | 给会话发消息；运行中入队，空闲时启动新一轮 |
| `session_edit_create` | 在调用者 cwd 的严格子目录建普通会话；该目录注册为 DSH workspace，并写 owner 记录 |
| `session_edit_delete` | 归档一个自己/子/owner 会话；`purge` 再尝试删 session 目录和投影缓存 |
| `session_edit_cleanup` | 批量归档/清理本进程内自己创建的会话与在线直接子会话 |

权限：调用者自己、header `parentSession` 等于调用者的直接子会话，或带 `plugin:edit-page/owner` 记录的会话。窗口只在插件内存里维护，不自动注入父上下文，也不写 `system/message`；模型不调 `poll` 就看不到新内容。`purge` 在会话仍占用日志句柄时可能只完成归档，`purged=false` 并返回原因。

## 生效方式

- 每次保存向会话追加一条 `plugin:edit-page/change` 记录（`ignorable` 插件记录，不进 surface、不改原文），并等待一次落盘。
- 插件注册的消息投影在折叠历史时把目标块替换成改后内容（文本或工具调用），所以模型下一轮直接使用改后内容，不用重启。
- 关掉插件或卸载插件后，这些记录被静默跳过，历史回到原文；重新启用后投影重新注册，改稿回来。
- 因此「重启 DSH 后编辑仍在」的前提是插件仍启用；编辑分页显示的就是投影后的版本。

## 边界

- 只能在会话已载入（打开着）时读写；未载入的会话返回 `SESSION_NOT_LIVE`，本页不提供离线改写。
- 模型正在运行时拒绝保存和分叉（`SESSION_RUNNING`），等这一轮结束再操作。
- 未保存草稿和页面状态（滚动、展开、原文预览）只暂存在当前页面进程内：刷新页面、退出 DSH 或停用插件都会丢弃，不写会话、不落盘；只有点「保存」才会追加 `plugin:edit-page/change`。
- 编辑页按窗口读取：默认一次 30 条，滚动落点按「视口顶部那条」记，不按像素；分页游标失效时（`WINDOW_STALE`）自动回到末尾窗口。
- 分叉只能从当前可见的模型回复出发（`NOT_OUTPUT`），分叉点之后写下的改稿记录会补进子会话；子会话打开后就是 Chat，可继续对话。
- 保存前比对当前投影内容，过期即拒绝（`STALE_TARGET`），页面自动刷新后重试。
- 被压缩摘要遮蔽的消息不再出现在列表里；保存时目标不可编辑会返回 `NOT_EDITABLE`。
- 修改思考块会剥掉块上及 `source.replayState` 里的签名，避免签名型 provider 拒绝请求。
- 工具调用只能改已有的名字和参数，不能新增或删除块；`id` 不可编辑，结果仍按原 `id` 配对。
- 工具调用组以思考块、文字块和用户消息为界，聚合同一区间里连续的调用，可以跨多条助手回复；组默认收起。整条内容都是调用、且被并进前一组的回复不再单独显示，也没有「分叉」按钮。
- 工具名去首尾空白后不能为空；参数必须是 JSON 对象，数组、标量、非法 JSON 一律拒绝（`400`）。
- 改调用不会重新执行工具，也不改已有结果；结果只读，超过 4000 字截断显示，没有配对结果时显示「没有配对的结果」。
- 改工具调用同样剥签名：剥掉 `source.replayState` 里该块的 `thoughtSignature`，保留 `namespace`。
- 停用插件只关投影开关、不注销：注销会让已用过该投影的会话在下一次折叠时报 `projection ... was removed`。投影由根上下文上的看护插件注册（进程级），停用编辑插件不影响它；已经打开的会话会保留上一次的投影结果，重新载入会话或重启 DSH 后回到原文。
- HTTP 路由带 `/v1` 前缀，并且挂在插件的 effect 上：热重载会先撤掉旧路由，避免旧闭包对着已停用的上下文取服务。
- 对话（Chat）视图只渲染原始事件，不渲染消息投影；改后的内容在本分页与模型侧生效，Chat 里仍是原文。
